## 🧠 System Design Philosophy

I approach software as **systems, not features**.

My focus is on building architectures that:
- Scale **by design**, not by patchwork
- Reduce repetition through **generic engines & metadata**
- Keep business rules **outside controllers**
- Remain readable for the *next developer*, not just the current sprint

### How this shows up in my work:
- 🔹 Generic CRUD engines instead of copy-paste APIs
- 🔹 Policy-driven authorization (RBAC outside route handlers)
- 🔹 Metadata-driven frontend forms instead of hardcoded UIs
- 🔹 Strong separation of concerns (UI, data, business logic)
- 🔹 Audit logging and lifecycle hooks baked into the core

> “Good architecture should make the right thing easy — and the wrong thing hard.”
